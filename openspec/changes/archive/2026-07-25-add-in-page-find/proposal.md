## Why

Pressing Ctrl-f in the review GUI does nothing: WebKitGTK (the webview the app
runs in) does not wire up the browser's native find dialogue. A reviewer reading
a long diff has no way to jump to an occurrence of a symbol, a filename, or a
phrase in a comment, which is a basic expectation for a code-review surface and
directly costs review speed — one of the project's stated goals.

## What Changes

- Pressing **Ctrl-f** opens an in-page find bar — an overlay pinned to the
  top-right of the window, mirroring a browser's find bar — since the native
  one is unavailable. The bar has a text input, an "n of m" match counter, and
  previous / next / close controls.
- Typing in the bar searches the **whole page** for **case-insensitive**,
  non-overlapping matches, highlights every match in place, and selects the
  first. The counter reflects the match total and the active position; a
  non-empty term with no matches reads "No matches".
- **Enter** / **F3** and **Shift+Enter** / **Shift+F3** (and the prev / next
  buttons) step the active match forward / backward with **wraparound**,
  scrolling it into view. Enter/Shift+Enter act from the input; F3/Shift+F3 act
  globally (the common browser find-again idiom), and F3 opens the bar if it is
  closed. The active match is styled distinctly from the rest.
- **Escape** or the close button closes the bar, removes every highlight,
  restores the page DOM to exactly its prior state, and returns focus to the
  diff so the next keypress scrolls the page.
- Search scope is the whole application page (`#app`) — the diff text, the
  embedded comment threads, the file list, and the header — staying as close to
  the native browser find (which searches the entire document) as possible. The
  find bar's own controls and hidden elements (e.g. the collapsed change banner)
  are excluded.
- Highlighting operates at the text-node level so it composes with the existing
  syntax-highlight spans. A match within a single highlight token is marked; a
  match straddling a token boundary is not joined — a rare, accepted limitation
  noted in code.

## Capabilities

### New Capabilities
- `in-page-find`: a self-provided Ctrl-f find over the whole page — opening and
  closing the find bar, locating and highlighting case-insensitive matches,
  stepping the active match with wraparound and scroll-into-view (Enter/F3 and
  the buttons), the match counter, whole-page scope (diff, comments, file list,
  header; not hidden content or the bar itself), and restoring the DOM on close.

## Impact

- New frontend code: `ts/core/find.ts` (pure match-locating and index-stepping),
  `ts/render/find.ts` (the find bar and DOM highlighting), with tests in
  `ts/core/find_test.ts` and `ts/render/find_dom_test.ts`.
- `ts/main.ts`: keyboard wiring for Ctrl-f (open), F3 / Shift+F3 (step / open),
  and Escape (close when focus has left the bar).
- `backend/assets/style.css`: find-bar and match-highlight styling.
- `backend/assets/index.html`: a `tabindex` on `#diff-view` so closing the bar
  can return focus to the diff.
- No backend (Go) or RPC changes; no new dependencies. The bundled
  `backend/assets/review.js` is regenerated by the existing build.
